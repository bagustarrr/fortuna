# KURSOR — Диагностика способностей

Контекст проекта для Claude Code. Подхватывается автоматически в каждой сессии.
Полная версия с историей решений — в `КОНТЕКСТ.md` (читать при работе над backend/amoCRM
и при спорных продуктовых вопросах).

---

## Что это

Интерактивная диагностика познавательных способностей ребёнка для школы
программирования KURSOR (Астана, 1000+ учеников, резидент Astana Hub).

**Бизнес-задача:** поднять доходимость на мастер-класс с ~40% до 60–70%.

**Механика:** лидоруб записал родителя на мастер-класс → родителю уходит ссылка →
ребёнок дома проходит тест 8–12 минут → родитель видит **часть** результата
(3 сильные стороны + закрытый профиль) → полную расшифровку даёт специалист лично
на мастер-классе. У родителя появляется личная причина прийти, которую нельзя
отложить и нельзя получить онлайн.

---

## Красные линии (не нарушать)

1. **Результат честный, но раскрыт частично.** Ребёнок реально проходит задания,
   система реально считает профиль по поведению. Ничего не выдумываем: родители в
   Астане общаются, дети сравнивают экраны. Два ребёнка с разными ответами и
   одинаковым результатом = репутация «гадалки».
2. **Слабые стороны письменно не отдаём никогда.** Только устно у специалиста.
   Профиль устроен так, что у любого ребёнка что-то будет наверху (нормировка
   внутри его собственного профиля) — плохого результата не получает никто, и
   никто не соврал.
3. **Никаких психологических/медицинских диагнозов.** Дисклеймер в коде обязателен.
4. «Специалист» на встрече — методист/преподаватель/руководитель учебного отдела,
   НЕ психолог (если нет образования).
5. **Никаких localStorage/sessionStorage** — в боевой версии состояние в Supabase.
6. Никаких выдуманных госпрограмм, регалий, цифр.

## Возрастные версии (без пересечений)

| Ключ     | Возраст | Цвет | Особенности |
|----------|---------|------|-------------|
| `junior` | 6–8     | зелёный | Крупнее, меньше абстракции, меньше заданий, ~6–8 мин |
| `middle` | 9–11    | оранжевый | Базовая версия. Циклы есть, условий мало, ~10–12 мин |
| `senior` | 12–17   | бирюзовый (исходный) | Максимум: циклы + условия, поиск ошибки, полные термины, ~12 мин |

Версия выбирается по `child.age` функцией `ageKeyFor(age)`. Всё, что различается
между версиями, лежит в одном конфиге `AGES` — новые задания добавлять туда,
а не хардкодить в компонентах.

**Цвета — в `PALETTES`.** `applyPalette(ageKey)` вызывается один раз в `App` до
первой отрисовки и подменяет содержимое объекта `C`; компоненты читают `C` как
обычно, менять их не нужно. Ключи (`teal`, `amber`) — исторические имена ролей,
а не цветов: `teal` всегда «основной акцент», `amber` — «тёплый акцент».

Два набора цветов в палитре **функциональные, не декоративные**:
- `shapes` — три цвета фигур в «Закономерностях». На них построено правило
  «чередование цвета», поэтому все три обязаны различаться и по тону, и по
  светлоте. `npm run validate` проверяет попарный контраст (≥ 1.6).
- `ok/bad/okSoft/badSoft` — «верно/неверно». Зелёный и красный во всех темах,
  это смысл, а не оформление.

Фон страницы до загрузки скрипта красит инлайн-скрипт в `scripts/template.html` —
иначе детская версия мигнёт «взрослым» фоном. Цвета там продублированы, менять
парой с `PALETTES`.

## Состав теста

`diagnostika_kursor.jsx` — один React-компонент (default export `App`).
Поток стадий строится динамически из `AGES[key].flow`.

**Блок 1 «Как ты думаешь»** — 3 мини-игры:
| Игра | Компонент | Что меряет |
|------|-----------|-----------|
| Закономерности (ряд фигур с пропуском) | `Patterns` | ИНД-02 |
| Последовательность (повтори порядок вспышек) | `Memory` | РП-04 |
| Пространство (счёт кубиков + мысленное вращение) | `Spatial` | МРТ-03 |

**Блок 2 «Алгоритмы»** — 3 мини-игры:
| Игра | Компонент | Что меряет |
|------|-----------|-----------|
| Робот (собрать программу, довести до цели) | `Robot` | ДКМ-01 |
| Поиск ошибки (найти неверную команду в готовой программе) | `Debug` | ВРФ-05 |
| Порядок шагов (расставить алгоритм по порядку) | `Order` | ДКМ-01, СТП-11 |

**Вопросы** (`Q1_POOLS`, `Q2_POOLS`) — по несколько формулировок на возраст;
разный текст, одно измеряемое значение (`v`). Меряют стиль мышления.

**Самооценка** — «сколько решил правильно» → сравнивается с реальностью (МКР-13).

**Экраны-инструкции** (`HowTo` + `EXAMPLES`) — перед каждой мини-игрой правила
показываются на живом примере. Без них дети не понимают задание.

Задания **генерируются заново при каждом прохождении** (`buildPatterns`,
`buildMemory`, `buildSpatial`, пулы уровней робота) — у двух детей будут разные
фигуры и уровни при одинаковой сложности.

## Шкалы (14 параметров)

Измеряются (11): ДКМ-01 декомпозиция и алгоритмизация, ИНД-02 индуктивный вывод,
МРТ-03 мысленное вращение, РП-04 рабочая память, ВРФ-05 верификация и поиск ошибок,
ТФР-06 толерантность к фрустрации, КБГ-08 когнитивная беглость, БСТ-09 баланс
скорости и точности, АНН-10 адаптивность к нарастающей нагрузке, СТП-11 стратегия
планирования, МКР-13 метакогнитивная рефлексия.

Закрыты до разбора (3): УПВ-07, ЛКО-12, ПКН-14 — константы в `LOCKED`.

Главное: **часть шкал считается из ПОВЕДЕНИЯ, а не из правильности** — сколько раз
пробует после неудачи, как меняется темп к концу, сам ли догадался свернуть
повторы в цикл. Это и делает продукт диагностикой, а не тестом.

НЕ измеряем: трудолюбие, доброту, ответственность — кликами не меряется,
пришлось бы врать.

Расчёт — `compute(data, n)`. Нормировка 0–100 внутри профиля одного ребёнка,
с мягким сжатием у верхнего края (`clamp`), чтобы сильные не слипались в 97.

## Экран результата

**Показываем:** шапка-заключение (имя, возраст, дата), 3 сильные стороны с кодами
и шкалами, «Что зафиксировала система» (реальные наблюдения из данных),
рекомендованное направление (ЗАКРЫТО), блок «Разбор на встрече».

**Прячем** (blur + замок): остальные параметры, расшифровку, направление.

Наблюдения в `compute()` формируются **только из фактов сессии** и согласованы по
роду (`сам/сама`) через хелпер `v()`. Добавляя наблюдение — убедись, что оно
следует из данных, а не из красивой формулировки.

`declineName()` — падежи + род, учитывает казахские женские имена на согласный
(Айгерим, Айгуль — не склоняются). `yearsWord()` — «лет/года/год».

## Данные ребёнка

В `App` — `readChild()`: имя, возраст, пол. Сейчас дефолт захардкожен, но можно
переопределить параметрами в адресе: `?name=Айгерим&age=7&gender=f`.
Читается и `?age=7`, и `#age=7` — при открытии файла с диска (file://) и на
части хостингов query-строка теряется, а хэш доходит всегда.

Если параметры заданы, на интро появляется плашка «Версия 6–8 лет · Имя, N лет».
По боевой ссылке из amoCRM параметров нет — и плашки нет. В боевой версии
данные придут из amoCRM.

**Показать три версии заказчику:** `…/#age=7`, `…/#age=10`, `…/#age=15`.

## Стек и сборка

- React + Vite. Только inline-стили, без внешних CSS-файлов.
- `index.html` — самодостаточный файл (React + код вшиты), деплой на Netlify
  перетаскиванием.
- **Пересобрать после правки jsx:** `node build.mjs` (нужен `npm i react react-dom esbuild`).
  Скрипт бандлит `diagnostika_kursor.jsx` через esbuild и вставляет в шаблон `index.html`.
- Проверка вёрстки — прогон через jsdom кликами по всему пути (`smoke.mjs`).

## Что дальше (по приоритету)

**Поток 1 — фронт:** ✅ 3 мини-игры в блоке · ✅ три возрастные версии ·
☐ проверить тайминг на живых детях (8–12 мин).

**Поток 2 — backend (после уточнения полей amo):**
Supabase (Postgres + API, free tier). amoCRM webhook → сервер создаёт разовую
ссылку с данными из карточки → ссылка в поле карточки → результат падает обратно
в amo. Ссылка сгорает **после завершения** теста, не после открытия; брошенный на
середине тест можно продолжить. Статусы для лидоруба: не открыт → начат → пройден
(фильтр «не открыт» за 2 дня до встречи → обзвон спящих).

**Поток 3 — замер эффективности:** первые 2–3 потока давать тест ПОЛОВИНЕ
записавшихся и сравнивать доходимость с контрольной группой. Иначе не отличить
эффект теста от «удачной группы».

**Открытые вопросы к заказчику:** названия кастомных полей в amo, название
этапа-триггера, один ребёнок = одна сделка?, дедлайн ссылки по времени, дата
встречи из amo при каждом открытии или заморозка, кто заводит Supabase.
